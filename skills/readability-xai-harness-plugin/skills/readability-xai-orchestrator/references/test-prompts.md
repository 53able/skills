# スキル検証用プロンプト例

## Should-trigger（オーケストレータ）

1. 「この規約を一般向けに読みやすくして。arXiv の XAI ナラティブみたいに多エージェントで回して」
2. 「長い論文のこの節を、忠実性を保ちつつ高校生でも読めるように反復改善して」
3. 「faithful evaluator と coherence を回す読みやすさハーネスで処理して」

## Should-NOT-trigger（近傍）

1. 「この関数の時間計算量だけ説明して」（ソース文章の読みやすさ改善ではない）
2. 「PDF をマージして」（PDF 専用スキル領域）
3. 「要約して」だけで、忠実性ループや multi-agent を求めていない短文

## With-skill / Without-skill 比較の観点

- With: `_workspace` にラウンドごとのレポートが残り、誤りが減少する軌跡がある
- Without: 一度きりの要約になり、数値ハルシネーションの自己修正が弱い
