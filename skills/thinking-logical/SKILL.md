# ロジカルシンキング（論理的思考）

> **核心**: 論点設定 → 情報収集 → 解釈 → 構造化

## 実行プロトコル

```
1. [論点設定]
   解くべき問いを明確化する
   例: 「新規登録フローをどう改善すべきか？」

2. [情報収集]
   論点に関連する事実を収集する
   - 定量データ: 離脱率、所要時間
   - 定性データ: ユーザーフィードバック

3. [解釈]
   収集した情報を解釈する
   - So What?（だから何？）: 事実から示唆を導く
   - Why So?（なぜそうなる？）: 示唆の根拠を確認

4. [構造化]
   解釈結果を論理的に構造化する
   - 結論を先に置く（ピラミッド構造）
   - 根拠を階層的に整理

5. [検証]
   論理の飛躍がないか確認する
   - 結論と根拠のつながりは妥当か？
   - 見落としている観点はないか？
```

## So What / Why So の使い方

```
事実: 「新規登録の離脱率が70%」
         ↓ So What?（だから何？）
示唆: 「登録フローに改善余地がある」
         ↓ Why So?（なぜそう言える？）
根拠: 「業界平均の離脱率は40%」
```

```markdown
### 収集した情報
| 種別 | 内容 | 出典 |
|------|------|------|
| 定量 | ... | ... |
| 定性 | ... | ... |

### 解釈（So What / Why So）
1. [事実] → [示唆]
2. [事実] → [示唆]

### 結論
[論点に対する回答]

### 根拠の構造
```
結論: [...]
├─ 根拠1: [...]
│   └─ 事実: [...]
├─ 根拠2: [...]
│   └─ 事実: [...]
└─ 根拠3: [...]
    └─ 事実: [...]
```

### 推奨アクション
1. [具体的なアクション]
```

## 併用パターン

| 併用する思考法 | 役割 |
|--------------|------|
| MECE | 情報収集時の漏れ防止 |
| クリティカルシンキング | 論理の飛躍を検証 |
| メタ思考 | 論点設定の妥当性を確認 |

## アンチパターン

| やりがち | 問題 | 対策 |
|---------|------|------|
| 論点を曖昧にしたまま進む | 議論が発散する | 最初に「問い」を1文で定義 |
| 事実と意見を混同 | 根拠が弱くなる | 出典を明記する |
| 結論を後回し | 伝わりにくい | ピラミッド構造で結論を先に |
