# 完成図の制作と描画確認

## 形式を選ぶ

- Mermaid: 関係、分岐、手順、時系列が中心で、自動配置でも読める場合。
- SVG: 層・包含・空間配置や注釈位置を細かく制御する必要がある場合。

指定形式を優先し、ブリーフの `explanation.output_format` と納品ファイルを一致させる。既存の描画環境を使い、特定ツールのインストールや新規依存を前提にしない。静的な図を標準とする。

## SVG

1. UTF-8の `.svg` を作り、`xmlns="http://www.w3.org/2000/svg"` と `viewBox` を付ける。
2. `<title>` と `<desc>` を書き、ルートから `role="img"` と `aria-labelledby` で参照する。説明には主要な関係・変化・結論を含める。
3. 意味を担う図形またはそのグループのIDをブリーフの要素IDと対応づける。タイトル・凡例・注釈は補助テキストとして区別する。
4. ラベルに十分な余白を取り、長い日本語は意味を保った改行にする。色だけで区別せず、ラベル・線種・形などを併用する。
5. XMLとしてパースできることを確認した後、実際の表示を確認する。構文成功だけでは文字の収まりや可読性は分からない。

標準ライブラリでの構文確認例:

```bash
python3 - <<'PYCODE'
from xml.etree import ElementTree
ElementTree.parse("diagram.svg")
print("SVG XML parsed")
PYCODE
```

## Mermaid

1. UTF-8の `.mmd` を作り、ノードIDをブリーフの要素IDと合わせる。ラベルと矢印の意味を明示する。
2. タイトル・凡例・注釈を使う場合は、意味を担うノードと区別する。表示に必要な短い説明・代替テキストも添える。
3. 利用可能なレンダラーで描画する。環境に応じて既存のプレビュー、Mermaid対応ビューアー、既存CLIを使い、生成したSVG・PNGなどの表示成果物を保存する。SVGを書き出した場合は、XMLとしてパースし、そのファイル自体を開いて確認する。
4. レンダラーが未対応の構文を使っていれば対応する構文に直す。表示できても、分岐条件・ラベルの対応・並びを目視で確認する。

## 実描画の確認

まず環境が提供するプレビュー・ブラウザー機能を使う。ブラウザー確認が必要で、プロダクト固有のプレビューがある場合はそれを優先する。図ファイルを表示し、想定する掲載サイズと縮小表示で確認する。

- 文字の欠け・はみ出し・意図しない改行がないか。
- 矢印の先端・方向・関係ラベルが判別できるか。
- 線の交差や近接で対応先を取り違えないか。
- 囲みや層が包含・順序・優劣について誤った意味を与えないか。
- 色を区別しにくい場合もラベルや線種で意味が追えるか。

表示サイズ、使用した描画手段、確認したファイル、結果を記録する。可能ならスクリーンショットを残す。スキル同梱の `references/review-checklist.md` で意味照合を別に行う。

## 描画できない場合

描画手段がなければ、図のソースファイルと短い説明・代替テキストを渡し、「描画未確認」と明記する。実施できた構文検証と意味照合だけを記録し、文字の収まりや可読性を合格扱いにしない。Mermaidの表示成果物が作れなかったことも残課題として報告する。

## 検証記録の例

```text
構造: ブリーフ検証成功（実行コマンドを記載）
意味: 入力の主要な主張・分岐条件・矢印を照合、矛盾なし
描画: 使用したビューアー名、確認ファイル、表示サイズを記載
修正: 1回、条件ラベルの位置を調整して再確認
残課題: なし / 未確認箇所と影響を記載
状態: 完了 / 描画未確認 / 未完成
```

この例は記録形式であり、実行していない確認を埋めてはならない。
