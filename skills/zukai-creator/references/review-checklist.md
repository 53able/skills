# 図解レビュー・チェックリスト

ブリーフの構造、説明の意味、描画の見え方を別々に確認する。スキル同梱の `scripts/check-diagram-brief.py` が成功しても、意味や描画の合格を保証しない。

## 意味の照合

- [ ] 読者の問いと理解のつまずきが具体的で、図がその問いに答える。
- [ ] 主要な主張が `source_basis` と `claim_visual_map` を通じて入力と要素へ追跡できる。
- [ ] 要素・線・注釈がソースの主張に沿い、根拠のない因果・数値・優劣を追加していない。
- [ ] 因果、順序、包含、関連、比較、依存を混同していない。
- [ ] 矢印の方向と関係ラベル、分岐条件、状態の前後が一致している。
- [ ] 意味を担う要素の図形とラベルが対応し、同じ種類に同じ形を使っている。タイトル・凡例・注釈・関係ラベルは補助テキストとして区別できる。
- [ ] 省略・比喩・適用範囲・未確定事項を明示している。

## 描画の確認

実際に表示した成果物を確認する。表示していない項目にはチェックを付けない。

- [ ] 想定掲載サイズと縮小表示でラベルが読み取れ、文字の切れ・はみ出しがない。
- [ ] 省略や改行で意味が変わらず、同じ要素の表記が一致している。
- [ ] 矢印の先端、条件、関係ラベルが判別でき、線やラベルの重なりで対応先を取り違えない。
- [ ] 近い関係が近くに配置され、要素数や補助表示が問いの理解を邪魔しない。
- [ ] グループ化、形、色、線種、文字の強調が一貫している。
- [ ] 十分なコントラストがあり、色だけで関係や状態を区別しない。
- [ ] SVGのタイトル・説明、またはMermaidに添えた代替テキストが図の意味を伝える。

## 修正と終了条件

1. 意味の逆転、根拠のない主張、読めない主要ラベルを優先して修正する。
2. 修正は最大3回を目安とし、各回で意味と描画を再確認する。検証に必要な環境が使えなければ、その範囲を記録する。
3. 重大な誤りが残る図は「未完成」として理由と必要な修正を示す。実表示ができなければ「描画未確認」と記す。未確認を合格にしない。
4. 重大な誤りがなく必要な確認ができたら納品する。軽微な残課題も記録し、完全性や満点を保証しない。

記録には、確認したファイル、方法、表示サイズ、意味の照合結果、修正回数、未確認事項、残課題、完成状態を含める。スキル同梱の `references/rendering-guide.md` の記録例を使える。

## 任意の診断採点（100点満点）

点数は改善箇所を探すために使う。完成判定は上の確認結果で行い、高得点で重大な誤りや未確認事項を相殺しない。未確認の項目は点数を付けず、確認済みの点数と未評価の配点を分けて報告する。

| カテゴリ | 配点 | 診断する点 |
|---|---|---|
| 図形と文字列の整合性 | 40 | 要素とラベル、形の意味、矢印の方向、文字の収まり（各10） |
| 意味の正確性 | 25 | 問いへの回答（5）、要素と注釈の役割（5）、ソース忠実性（10）、表現の意味の一貫性（5） |
| 認知負荷とレイアウト | 20 | 情報量、配置と交差、グループ化、補助表示（各5） |
| 表記とスタイル | 15 | ラベルの粒度（5）、文字サイズと太さ（5）、コントラスト（3）、誤読を防ぐ注釈（2） |

診断を使った場合は実点と失点理由を添える。100点になるまでの反復や、実行していない確認の採点を求めない。第三者の確認が得られる場合は、問いへの回答と誤読箇所の指摘を改善に使う。
