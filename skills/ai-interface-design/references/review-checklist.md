# AIインターフェース検証チェックリスト

## 1. 目的と能力

- [ ] 主要利用者と達成したい結果が定義されている。
- [ ] AIが不要な代替手段を検討している。
- [ ] できること、不得意、対象外が区別されている。
- [ ] データ範囲、更新時点、利用上限、費用が必要な時点で分かる。

## 2. 入力と文脈

- [ ] AIへ渡る文脈を確認・除外できる。
- [ ] 記憶と一時文脈を区別している。
- [ ] 自由入力と直接操作の役割が定義されている。
- [ ] 頻出タスクにテンプレートまたは具体的な開始例がある。

## 3. 計算と進捗

- [ ] 実行中、待機中、承認待ち、完了、失敗を区別できる。
- [ ] 長時間処理から離脱して再開できる。
- [ ] 架空の進捗率を表示しない。
- [ ] 完全な実行記録を必要に応じて確認できる。

## 4. 出力と信頼

- [ ] 根拠と適用範囲を主張の近くで確認できる。
- [ ] 出力の一部を修正、比較、破棄できる。
- [ ] 下書き、提案、実行済みを区別できる。
- [ ] 流暢さ、説明量、Chain-of-Thoughtを正しさの証拠にしていない。
- [ ] 過信と過小利用の両方を評価対象にしている。

## 5. 行動と権限

- [ ] 操作をR0〜R3へ分類している。
- [ ] 高影響操作の対象、引数、理由、期間、費用が承認前に分かる。
- [ ] 承認、編集、拒否の結果が明確である。
- [ ] 拒否した操作を別経路で再実行しない。
- [ ] 許可を後から確認・取消できる。
- [ ] 承認疲れを減らす設計と測定方法がある。

## 6. 共有制御と回復

- [ ] 一時停止、再開、中止、引き継ぎが定義されている。
- [ ] 入力、文脈、途中成果、成功済み工程を保存する。
- [ ] 可逆な状態は版またはチェックポイントへ戻せる。
- [ ] 不可逆な副作用には取消または補償操作がある。
- [ ] 重複実行と再開時の二重副作用を防ぐ。

## 7. セキュリティと監査

- [ ] ファイルとネットワークの境界がモデル外で強制される。
- [ ] 資格情報が用途と期間で制限されている。
- [ ] 間接プロンプトインジェクションを脅威として扱う。
- [ ] 提案、承認、実行、失敗、取消を追跡できる。
- [ ] 監査ログへ機密情報を無条件に残さない。

## 8. 倫理とアクセシビリティ

- [ ] データ利用、記憶、削除、異議申立て、救済が定義されている。
- [ ] 非利用者、データ主体、脆弱な利用者への影響を検討している。
- [ ] キーボードだけで主要フローを完了できる。
- [ ] 状態更新が支援技術へ通知される。
- [ ] 色、ドラッグ、音声、画像、時間制限へ代替手段がある。
- [ ] 未実施の専門監査を合格済みと記載していない。

## 9. 最小シナリオ

- [ ] 正常系: 目的を達成できる。
- [ ] 誤解系: AIの意図解釈ミスを実行前に修正できる。
- [ ] 誤出力系: 流暢だが誤った結果を検証・破棄できる。
- [ ] 副作用系: 高影響操作を実行前に止め、拒否できる。
- [ ] 復旧系: 途中失敗後に成果を失わず再開できる。
- [ ] 権限系: 許可不足と許可取消後の挙動が安全である。

## 10. 証拠

- [ ] 各受入条件に検証方法、責任者、証拠、停止条件がある。
- [ ] 実行した検証と未実施の検証を分けている。
- [ ] タスク完了率、修正時間、誤承認、未承認副作用、復旧率を必要に応じて測る。
- [ ] 成功閾値を業務の影響度と可逆性に合わせている。
