# クリティカルシンキング（批判的思考）

> **核心**: 論理展開 → 論点・前提・飛躍を疑う

## 疑うべき3つのポイント

```
1. 論点
   → 問い自体は正しいか？
   → そもそも問題設定が間違っていないか？

2. 前提
   → 暗黙の前提は妥当か？
   → 事実として正しいか？

3. 飛躍
   → 結論と根拠のつながりに飛躍はないか？
   → 「なぜそう言えるか」が説明できるか？
```

## 実行プロトコル

```
1. [主張の特定]
   検証対象の主張・結論を明確にする
   例: 「キャッシュを導入すればパフォーマンスが改善する」

2. [根拠の確認]
   主張を支える根拠を列挙する
   - 「現在DBクエリに時間がかかっている」
   - 「同じデータへのアクセスが頻繁」

3. [論点の検証]
   問い自体が正しいか確認
   - この問題を解くべきか？
   - 問題の設定は適切か？
   - 別の問いを立てるべきではないか？

4. [前提の検証]
   暗黙の前提を洗い出し検証
   - 「DBクエリが遅い」は本当か？（計測したか）
   - 「キャッシュが効く」は本当か？（更新頻度は？）

5. [飛躍の検証]
   結論と根拠のつながりを検証
   - 「DBが遅い→キャッシュで解決」は飛躍していないか？
   - 他の原因（N+1、インデックス不足）は検討したか？
```

## よくあるバイアス

| バイアス | 説明 | 対策 |
|----------|------|------|
| **確証バイアス** | 自分の仮説を支持する情報ばかり集める | 反例を積極的に探す |
| **正常性バイアス** | 「大丈夫だろう」と楽観視 | 最悪のケースを想定 |
| **サンクコスト** | 投資した分を回収しようとする | ゼロベースで評価 |
| **権威バイアス** | 偉い人の意見を無批判に受け入れる | 根拠を確認する |
| **生存者バイアス** | 成功例だけを見る | 失敗例も調査 |

## 併用パターン

| 併用する思考法 | 役割 |
|--------------|------|
| 演繹的思考 | 前提から結論への論理を確認 |
| MECE | 検証すべき観点の漏れを防ぐ |
| PAC思考 | 前提・仮定・結論の分離 |

## アンチパターン

| やりがち | 問題 | 対策 |
|---------|------|------|
| 批判しすぎて動けない | 分析麻痺 | 期限を設けて結論を固定 |
| 人格攻撃になる | 建設的でなくなる | 「アイデア」を批判、人を批判しない |
| 細部にこだわりすぎ | 本質を見失う | 影響度の高い点に集中 |
| 代案なき批判 | 前に進めない | 批判には改善案をセットで |

## 注意

**批判的 ≠ 否定的**

クリティカルシンキングは「否定する」ことではない。「より良くするために検証する」こと。建設的な批判は、チームの意思決定の質を高める。
