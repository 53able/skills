# ジョブ理論イノベーション・エージェント アーキテクチャ

## コンテキストエンジニアリングの設計思想

このエージェントは単なるプロンプトの工夫を超え、LLMに与える指示・外部知識・ツール定義・過去の文脈（メモリ）を動的かつ構造的に組み立てる**コンテキストエンジニアリング**の原則に従い設計されている。

```
c_instr (システム指示)
  └── エージェントの役割・目的の定義

c_mem (メモリ)
  └── 4つの状態管理（Observation / Employment / Fired / Formulation）

c_tools (ツール定義)
  └── 6つの分析レンズ（生活観察・無消費・ネガティブ・意外な使われ方・感情・競合再定義）

c_state (推論ステート)
  └── Step 1〜4 の Chain-of-Thought プロセス
```

## ジョブ理論のコアコンセプト

### ジョブとは何か

顧客は「製品を買っている」のではなく、**特定の状況で特定の問題を解決するために製品を「雇用」する**。

```
❌ 従来の視点: 30代男性がドリルを買う
✅ ジョブ視点: 壁に穴を開けたい状況でドリルを雇用する
           （本当のジョブは「穴」ではなく「絵を飾りたい」かもしれない）
```

### 3層のジョブ構造

| 層 | 説明 | 例（コーヒーショップ） |
|----|------|----------------------|
| **機能的ジョブ** | 実際に行いたいタスク | カフェインを摂取したい |
| **感情的ジョブ** | 感じたい・避けたい気持ち | 一人で集中できる場所が欲しい |
| **社会的ジョブ** | 他者にどう見られたいか | 仕事ができる人に見られたい |

### 真の競合の定義

同じ製品カテゴリではなく、同じジョブを奪い合う代替品が「真の競合」。

```
マクドナルドの朝のシェイク
  ❌ 表面上の競合: バーガーキングのシェイク
  ✅ 真の競合: 通勤中に片手で食べられる朝食（バナナ・グラノーラバー）
```

## 対話戦略

### 質問の設計原則

- 一度に1〜2問に絞る（認知負荷最小化）
- 「なぜ」より「いつ・どんな状況で」を問う（状況の因果関係を掘る）
- ネガティブジョブから入ると本音が出やすい

### 収束フェーズの判定

以下が揃ったらStep 2（定式化）へ移行する：
- [ ] 顧客の具体的な状況が描けた
- [ ] 現在の雇用品とその不満が明確になった
- [ ] 少なくとも2つのレンズで分析できた

## 実例

### 例：学習塾

```
Observation: 中学受験を控えた子どもを持つ保護者が、子どもの学力に不安を感じている
Current Employment: 週2回の塾通い + 参考書
Fired Product: もし個別最適化AIが出たら、画一的な授業形式の塾を解雇する
Job Formulation: 「子どもの受験まで3ヶ月という状況で、子どもの苦手単元だけに集中しながら、
              合格という結果と親自身の安心感を同時に得たい」

真の競合: 週2塾 vs 家庭教師 vs 教育系YouTube vs 受験コーチング
```

### 例：フィットネスジム

```
Observation: 平日夜に仕事帰りでジムに立ち寄る30代会社員
Current Employment: 近所のジム月額会員
Fired Product: コロナ禍でオンラインヨガに乗り換えた際に通いのジムを解雇
Job Formulation: 「仕事帰りの疲れた状態で、移動コストをかけずに、
              健康維持と"今日もやった"という達成感を得たい」

真の競合: ジム vs ホームトレーニング vs 歩いて帰る vs ストレッチ動画
```
