# 不必要な保留文を避ける

## 目的

結論を弱める一般的な留保を、明確な判断と具体的な選択条件へ置き換える。読者の行動、解釈、安全性、費用、互換性、技術選択を変える制約だけを残す。

## 手順

**ステップ1：編集条件を確定する**
1. 対象文章、想定読者、支援する意思決定、編集可能な範囲を特定する。
2. 事実、引用、測定値、出典、書き手の確信度を維持する。
3. 根拠のない確実性を作らない。根拠が結論を支えない場合は、不確実性を削らず、根拠を求めるか主張の範囲を狭める。
4. 法的免責、医療リスク、正式な科学的不確実性、引用の忠実な再現を扱う場合は、この手順を止め、領域上必要な留保を維持する。

**ステップ2：保留文の候補を見つける**
1. 個別の文を直す前に、文章全体を読む。
2. 長文または候補の見落としが懸念される場合は、`python3 scripts/find_hedges.py 入力ファイル` を実行する。検出結果を自動削除の対象ではなく、確認候補として扱う。
3. 「状況によります」「一概には言えません」「可能性があります」「必ずしも〜ではありません」「環境によって異なります」などの反復表現を特定する。
4. 結論の直後に置かれ、具体的な選択条件を加えず一般的な不確実性だけを繰り返す文を特定する。

**ステップ3：各候補を分類する**
1. 分類に迷う場合だけ `references/decision-rules.md` を読む。
2. 各候補を次のいずれかに分類する。
   - **削除**：行動可能な条件を加えない一般的な不確実性。
   - **変換**：実在する制約を曖昧に表現した留保。
   - **維持**：行動、解釈、安全性、費用、互換性、技術選択を変える制約。
   - **確認**：根拠または専門知識なしでは解決できない不確実性。
3. 実在する境界条件が含まれる場合は、**削除**より**変換**を優先する。
4. 重要な制約は一度だけ示し、別の箇所で繰り返す保留文を削る。

**ステップ4：主張を書き換える**
1. 結論を先に書く。
2. 適用条件を、結論と同じ文または直後の文に置く。
3. 抽象的な不確実性を「XならAを選ぶ。YならBを選ぶ」という具体的な分岐へ変える。
4. 根拠が限定される場合は、対象、期間、環境、バージョン、用途を限定する。
5. 判断を避ける表現を、明確な推奨、非推奨、または追加検証の要件へ置き換える。
6. 確率そのものが解釈を変える場合は、校正された確率表現を維持する。

**ステップ5：書き換えを検査する**
1. 読者が「何を選ぶか」「次に何をするか」を答えられるか確認する。
2. 残した留保が意思決定を変えるか、重大な損失を防ぐか確認する。
3. 書き換え後の主張が根拠の範囲を超えていないか確認する。
4. 誤った断定に変わった文は、留保を戻すのではなく主張の範囲を狭める。
5. 仮想的な反論から書き手を守るだけの留保を削る。

**ステップ6：編集結果を返す**
1. 書き換えだけを求められた場合は、修正文を直接返す。
2. 変更理由も求められた場合は、`assets/revision-template.md` の構造を使い、重要な変更だけを示す。
3. 維持した制約と削除した一般的な留保を区別する。
4. 修正文の末尾へ、結論を再び弱める免責的な一文を追加しない。

## エラー処理

* `scripts/find_hedges.py` がファイルを読めない場合は、パスとUTF-8エンコーディングを確認して再実行する。
* スクリプトが候補を検出しない場合は、結論直後の文を手作業で確認する。保留は特定の語句ではなく文章構造に現れることがある。
* 保留を削ると根拠以上の断定になる場合は、主語、期間、環境、バージョン、用途を限定する。
* 制約がセキュリティ、データ損失、課金、対応OS・バージョン、結果の解釈、技術選択に影響する場合は、具体的な条件として残す。
* 原文が不確実性そのものを報告している場合は、その不確実性を維持し、精度だけを改善する。

## 検証

1. `python3 scripts/find_hedges.py 修正済みファイル --fail-on-match` を実行し、残った定型的な候補を検出する。
2. 検出された候補をすべて目視確認し、必要な留保には理由を付けて残す。
3. 根拠なしに事実、引用、数値、出典、確信度を変更していないことを確認する。
4. 最終文が「結論の後に一般論で後退する構造」ではなく、「結論と選択条件を示す構造」になっていることを確認する。
