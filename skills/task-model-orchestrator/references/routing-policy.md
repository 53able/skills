# 割り当て方針（ヒューリスティック、未実測）

優先順位: 人間確認 > 委譲しない > Opus > Sonnet > Haiku。高影響を「Opusなら無承認で実行可」と読み替えない。

| 状況 | 初期担当 | 根拠と境界 |
|---|---|---|
| 小さく、親が直接処理できる | 委譲しない | 起動・受け渡し・検証の固定費を避ける |
| 局所検索、定型変換、限定的なテスト追加。入力と合否が明確、可逆 | Haiku | 外部の検証で誤りを拾える場合のみ。探索は読み取り専用権限を与える |
| 複数ファイルの通常の実装、原因調査、部分設計、レビュー | Sonnet | 途中判断が必要。検証と変更範囲を固定する |
| 高度な設計の対立、重要な移行、失敗ログを伴う難問 | Opus | 複雑な判断へ能力を寄せる仮説。高影響操作の承認は別 |
| 破壊的、本番、秘密・個人情報の外部送信、不可逆、受入基準なし | 人間確認または停止 | モデル能力は権限・検証の代用ではない |

- 「計画は常に Opus、実行は常に Haiku」としない。実行側で難しい判断が必要なら上位モデルへ割り当てる。
- Agent ツールの呼び出し単位の `model` 指定が優先される。ただし管理者の availableModels や強制設定で別モデルになることがある。`/tasks` 等で実際のモデルを確認する。
- 呼び出し回数、入力/出力トークン、キャッシュ、再試行、並列競合、人間の修正を含めて比較する。課金契約によって費用の意味が異なる。
- サブエージェントの新規起動は独立したコンテキスト費用が発生する。小仕事を細分化しすぎない。
