# Garr Reynolds / Presentation Zen 原則

メイン手順だけでは判断しきれない場合に、この基準を読む。

## 中核三原則

- **抑制（Restraint）:** 必要なものは入れるが、それ以上は入れない。メッセージを支えない要素を取り除く。
- **簡潔さ（Simplicity）:** 明快さ、直接性、繊細さ、本質性、ミニマリズムを目指す。簡潔さを「浅くすること」と混同しない。
- **自然さ（Naturalness）:** 発表者がスライドを読むのではなく、聞き手に向かって自然に話せる状態を作る。

## 準備

- 聞き手を先に置く。聞き手の知識、関心、制約、発表後に起こしたい変化を定義する。
- 聞き手が一つだけ覚えるべき文を書く。
- 聞き手には見えなくても、発表者が使う構造を作る。
- 話が曖昧な場合は、いきなりスライドを磨かず、紙、付箋、ホワイトボードでスケッチ、ストーリーボード、並べ替え、削除を行う。

## スライド設計

- 投影スライドは視覚的な補助として扱い、文書として扱わない。
- slideumentを避ける。投影スライドと配布資料または詳細文書を分ける。
- 箇条書きの多い画面より、具体的なビジュアル、図、チャート、大きな画像、少ない文字を優先する。
- Signal-to-Noise ratioを高める。装飾的なロゴ、重複ラベル、太い罫線、弱いアイコン、埋め草の文字を取り除く。
- 後ろの席から見えるように設計する。大きな文字、明確なコントラスト、一つの焦点、短時間での理解を優先する。
- コントラスト、余白、三分割法、目的を持った色、控えめなアニメーションで注意を誘導する。
- チャートには **restrain / reduce / emphasize** を適用する。

## ストーリーとデリバリー

- 冒頭で引き込む。問い、緊張、具体的な場面、意外な観察、明確な問題を使う。
- 可能な場合は、対立、賭け金、理解の穴を示す。
- 望ましい変化を明示する。変化は、理解、意思決定、行動、優先順位、感情のいずれでもよい。
- スライドは発表者に従属させる。詳細はスピーカーノートに置いてよいが、スライドをテレプロンプターにしない。
- 最後は意図して終える。中心メッセージと次の行動に戻る。

## 注意点

- 技術、法務、医療、金融、科学上必要なニュアンスを消さない。
- 検証詳細が投影スライドに収まらない場合は、補足文書、付録、リンクを使う。
- 非同期で読まれる場合は、ライブ用スライドだけに頼らず、文書または注釈付きデッキを作る。
