# Step 3: Green（テストを通す最小実装）

> **目的**: テストをパスさせる最小限のコードを書く。それ以上のことはしない。

## 絶対ルール

```
【この段階でやること】
✅ テストエラーメッセージを読む
✅ そのエラーを解消する最小のコードを書く
✅ テストを実行してパスを確認する

【この段階でやらないこと】
❌ 美しいコードを書こうとする
❌ パフォーマンス最適化をする
❌ DRYを気にする（後でRefactor）
```

## 実行手順

### 1. テストエラーメッセージを読む

エラーメッセージが「何を要求しているか」を理解する。

### 2. 最小のコードを書く

```typescript
// 「動く」ことだけを目指す
// 汚くてもいい、重複してもいい
```

### 3. テストを実行

```bash
pnpm <package> test <file>.test.ts
```

### 4. パスするまで繰り返す

1つのエラーを解消 → 次のエラーを確認 → 解消 → ...

## 完了条件

- [ ] 対象テストが全てパスしている
- [ ] 既存テストを壊していない
- [ ] 型エラーがない（`pnpm <package> typecheck`）

## よくある間違い

| NG | なぜダメか |
|---|---|
| 「ついでに」他の機能も実装 | スコープクリープ、テストがない実装が生まれる |
| コードの見た目を整える | それはRefactorフェーズでやること |
| 「将来必要になりそう」な機能を追加 | YAGNI違反、テストがない実装が生まれる |
