# ナラティブ・デッキからWeb記事への変換規則

必要なときだけ読み、プレゼンテーションと記事の媒体差を埋める。

## 基本原則

- スライドを記事の縮小版として扱わない。
- スピーカーノートを本文として貼り付けない。
- プレゼンテーションの一本道を記事の見出し順へ固定しない。
- 話者、声、間、会場、質疑応答に依存する情報を本文へ戻す。
- 物語の美しさより、主張と証拠の整合を優先する。

## 変換表

| プレゼンテーション側 | Web記事側での扱い |
|---|---|
| 中心メッセージ | タイトル、導入、結論の軸にする |
| 1ビートの主張 | 近い主張と統合し、読者の疑問単位で見出しを作る |
| スピーカーノート | 初稿の材料として段落へ書き直す |
| 図、デモ | キャプションと本文だけでも意味が通る説明を付ける |
| 口頭の反復 | 原則として削る |
| 聴衆への問い | 読者の疑問を代弁する見出しまたは導入へ変える |
| 質疑で補う内容 | 制約、判断基準、FAQとして先回りして書く |
| 話者の強調 | 語順、見出し、具体例、証拠の配置で表現する |
| 会場限定の文脈 | 記事だけで理解できる背景説明へ置き換える |

## 記事へ戻す情報

- 用語の定義
- 対象バージョン、環境、前提条件
- コードと実行方法
- 引用と直接URL
- 観察と推論の区別
- 代替案との比較条件
- 失敗条件、例外、未検証範囲
- 再現または採用判断に必要な情報

## 見出しの判定

見出しだけを読み、読者の問題、調査対象、証拠と判断、適用条件、次の行動が分かるか確認する。「背景」「詳細」「考察」のような抽象語だけなら、その節で答える問いまたは主張へ置き換える。

## 圧縮の判定

- 口頭のリズムのための反復を削る。
- 根拠、例外、再現条件は短さのために削らない。
- 段落ごとに、主張、説明、証拠、含意のどれを担うか確認する。
- 役割がない段落を削るか、役割を明確にする。
