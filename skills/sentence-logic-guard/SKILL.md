# 文脈論理ガード

## 目的

文章における論理を「事柄と事柄をつなぐ力」として扱う。次の一文が、直前の文によって生じた不足を補っているかを確認し、すでに書かれた内容への責任を保ちながら論理破綻を防ぐ。

## 手順

**Step 1: 点検対象を固定する**
1. 作業が執筆、推敲、レビューのどれかを特定する。
2. 想定読者、文章ジャンル、暗黙知をどこまで許すかを確認する。
3. 文章が提示されていない場合は、論理レビューを始める前に本文またはアウトラインの提示を求める。
4. 事実確認、出典確認、法的判断、数学的証明を求められた場合は、このスキルが文章のつながりだけを点検することを明示し、適切な別ワークフローへ回す。

**Step 2: 先へ進む前に、書いた文を振り返る**
1. 次の文を提案する前に、直前に書かれた文を読む。
2. 直前の文が生んだ不足を名づける。不足は、原因、例、主語、前提、対比、結果、限定の欠落として扱う。
3. 次の文がその不足をどう補うかを確認してから、評価または提案を行う。
4. 直前の文が作った縛りを受けず、思いつきだけで進む続き方を退ける。

**Step 3: 長い文章では文ペアを抽出する**
1. 文章が複数段落にまたがる場合、ローカルファイルがあれば `python scripts/sentence_pairs.py [input-file]` を実行する。
2. 文章がチャット内にしかない場合は、一時テキストファイルへ保存するか、隣接する文ペアを手作業で点検する。
3. 各ペアを、前の文、次の文、暗黙の橋渡しの順に確認する。
4. 橋渡しが欠けている、矛盾している、書き手の私的文脈に依存している、または読者の常識に頼りすぎている箇所を記録する。

**Step 4: 常識的判断のフィルターを通す**
1. 想定読者が、提示された文脈から次の展開を自然に予想できるかを確認する。
2. 「意外だが合図されている展開」と「根拠のない唐突な展開」を分ける。
3. 通常の期待を外す展開では、その前に合図、前提、原因、状況説明を追加する。
4. 皮肉、サスペンス、文学的な飛躍を消さない。必要なのは説明過多ではなく、読者が意図を追えるだけの合図である。

**Step 5: 読者の目で読み直す**
1. 自分以外の人が書いた文章として読み直す。
2. 書き手の頭の中にだけある前提が、本文の説明不足を埋めていないかを印づける。
3. 重要度の高い文章、または書き手が近づきすぎている文章では、時間を置いて読み直す工程を勧める。
4. 詳細な段落単位・文単位の点検が必要な場合は、`references/coherence-checklist.md` を読む。

**Step 6: 最小限に直す**
1. つながりを修復する最小編集を優先する。前提を足す、主張を狭める、文を並べ替える、接続表現を置き換える、過負荷な文を分ける。
2. 論理上必要な場合を除き、書き手の論点、語調、結論を保つ。
3. 観察と推論を分ける。本文上で見えるほころびを述べてから、修正案を出す。
4. 構造化レビューを求められた場合は、`assets/revision-report-template.md` を使う。

## 出力ルール

- 簡易レビューでは、`論理の状態`、`ほころび`、`最小修正案` の3項目で返す。
- リライトでは、原則として修正文と短い変更メモだけを示す。
- レビューでは、可能な限り段落番号と文番号で位置を示す。
- 別途ファクトチェックを行っていない限り、文章の内容が事実であるとは言わない。

## エラー処理

- `scripts/sentence_pairs.py` が入力ファイル未検出で失敗した場合は、見つからなかったパスを示し、正しいファイルまたは貼り付け本文を求める。
- 文分割が不完全な場合は、スクリプト出力を権威ではなくナビゲーション補助として扱い、手作業で補う。
- 文章が意図的にシュール、詩的、断片的である場合は、説明的な一貫性を強制せず、断絶の意図が読者に伝わるかだけを確認する。
- 判断に必要な文脈が足りない場合は、前提を発明せず、不足している読者前提を列挙する。
