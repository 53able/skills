# 文芸的プログラミングの背景原則

## 中核概念

- 文芸的プログラミングは、コードと説明を別々に管理せず、一つの文書に編み込む方法である。
- 文書は人間に向けた説明であると同時に、処理系によって実行可能なコードへ変換される対象でもある。
- Donald E. Knuth の WEB システムでは、文書化されたプログラムから TeX 文書を生成する処理を `weave`、コンパイラ入力用の Pascal ソースを生成する処理を `tangle` と呼んだ。
- コードの提示順序は、プログラミング言語の構文上の制約ではなく、人間が理解しやすい順序にできる。

## 重視する説明

- アルゴリズムの説明
- 正当性の証明または根拠
- 設計上の決定理由
- 代替案を採らなかった理由
- 失敗条件、境界条件、例外処理
- 保守時に守るべき不変条件

## 利点

- 説明を書きながら実装するため、実装者が別の角度からコードを検討できる。
- コードと説明が近接するため、修正時に説明も更新されやすい。
- ドキュメントがコードベース内で散逸しにくい。
- 保守段階で、通常のコメントより濃い設計情報を参照できる。

## 限界

- 執筆負荷が高く、通常の実装より時間がかかる。
- チームが生成手順や文書形式に慣れていないと、保守コストが増える。
- すべてのコードに適するわけではない。単純な glue code、短命な実験、定型的な CRUD では過剰になりやすい。
