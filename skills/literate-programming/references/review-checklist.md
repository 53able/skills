# 文芸的プログラミング レビューチェックリスト

## 物語性

- 問題設定が最初に示されている。
- 読む順序が人間の理解順になっている。
- 章や断片名が処理内容ではなく意図を表している。
- 唐突なコード断片がない。

## 意図と根拠

- 主要な設計判断の理由が書かれている。
- 採らなかった代替案が必要十分に説明されている。
- アルゴリズムの正当性または妥当性の根拠がある。
- 失敗条件と境界条件が明示されている。

## コードとの近接性

- 説明と対応するコードが離れすぎていない。
- コード変更時に更新すべき説明が分かる。
- 説明だけが古くなる危険な一般論が少ない。

## 実行可能性

- コード断片の取り出し方、実行方法、または生成手順が示されている。
- テスト、実行例、検証コマンドのいずれかがある。
- 未実行の結果が事実として書かれていない。

## 保守性

- 保守者が守るべき不変条件が明示されている。
- 変更しやすい点と壊れやすい点が区別されている。
- 説明が長すぎて実装の把握を妨げていない。
