# 演繹的思考

> **核心**: 大前提（一般論）+ 小前提（具体事実）→ 必然的結論

## 三段論法の構造

```
大前提: 全てのAはBである
小前提: CはAである
結論:   CはBである
```

**例: 設計への適用**

```
大前提: 「単一責任の原則に従うべき」（設計原則）
小前提: 「UserServiceが認証とプロフィール管理を担当している」（現状）
結論:   「UserServiceを分割すべき」
```

## 実行プロトコル

```
1. [大前提の確認]
   適用すべき原則・ルール・制約を明確にする
   - 設計原則（SOLID, DRY, etc.）
   - コーディング規約
   - ビジネスルール
   - 技術的制約

2. [小前提の収集]
   具体的な事実を収集する
   - 現状のコード構造
   - 要件・仕様
   - 環境の制約

3. [結論の導出]
   大前提と小前提から論理的に結論を導く
   「大前提 + 小前提 → したがって結論」

4. [前提の検証]
   導出した結論の妥当性を確認する
   - 大前提は本当に正しいか？
   - 小前提に誤りはないか？
   - 隠れた前提はないか？

5. [実装への適用]
   結論を具体的なコードに落とし込む
```

## 出力テンプレート

```markdown
## 演繹的推論

### 大前提（原則・ルール）
- [適用する原則1]
- [適用する原則2]

### 小前提（具体的事実）
- [現状・要件・制約1]
- [現状・要件・制約2]

### 推論過程
```
大前提: [...]
小前提: [...]
────────────
結論:   [...]
```

### 前提の検証
- 大前提の妥当性: [検証結果]
- 小前提の正確性: [検証結果]
- 隠れた前提: [あれば記載]

### 実装方針
[結論に基づく具体的な実装方針]
```

## 併用パターン

| 併用する思考法 | 役割 |
|--------------|------|
| クリティカルシンキング | 前提の妥当性を検証 |
| ディベート思考 | 異なる原則間のトレードオフを議論 |
| 帰納的思考 | 結論を実データで検証 |

## アンチパターン

| やりがち | 問題 | 対策 |
|---------|------|------|
| 大前提を疑わない | 誤った原則に従ってしまう | クリティカルに前提を検証 |
| 小前提の確認不足 | 現状認識の誤りで結論が歪む | コードを実際に読んで確認 |
| 原則の過剰適用 | 過度な抽象化・複雑化 | YAGNI原則とバランスを取る |

## 注意

**大前提が崩れると結論も崩壊する**

演繹は「正しい前提から必然的に結論を導く」手法。前提が間違っていれば、どんなに論理的でも結論は誤る。必ず前提の検証をセットで行うこと。
